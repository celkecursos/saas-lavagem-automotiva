TASK 6 - Identidade visual: paleta de cores (reaproveitada do projeto adm)
================================================================================

OBJETIVO
--------
Definir a paleta de cores do SaaS reaproveitando diretamente o que já é
usado no projeto celke-nota-corte-administrativo-v1-adm, em vez de criar
uma paleta nova do zero. Isso mantém consistência visual entre os
sistemas Celke e evita decisões arbitrárias de cor sem necessidade.

Framework de CSS: Tailwind CSS (mesmo do adm). Todas as cores, classes
utilitárias e componentes descritos abaixo pressupõem Tailwind — nada de
CSS customizado à mão fora do bloco theme.extend do tailwind.config.js e
das classes @apply em resources/css/app.css. O próprio scaffold padrão
do Laravel (Breeze) já vem com Tailwind configurado, então isso não
exige nenhuma instalação extra além do que a task-1 já prevê.

Esta decisão SUBSTITUI a paleta hex discutida anteriormente (Primária
#0F62FE, Accent #38BDF8, Sucesso #22C55E etc.) — nada daquilo chegou a
virar código, então não há nada para reverter, só seguir com a direção
abaixo a partir daqui.


1. CORES SEMÂNTICAS — BOTÕES, BADGES, ALERTAS (Tailwind puro)
------------------------------------------------------------------
São classes utilitárias do Tailwind sem hex customizado — mesmo padrão
usado no adm em resources/css/app.css. Replicar tal e qual neste projeto.

Botões:
  .btn-primary     bg-blue-500 text-white     hover:bg-blue-600
  .btn-danger      bg-red-500 text-white      hover:bg-red-600
  .btn-secondary   bg-gray-500 text-white     hover:bg-gray-600
                   (dark: bg-gray-600 hover:bg-gray-700)

Badges (uso solto em views, sem componente Blade dedicado no adm — mas
recomendo criar um componente <x-badge status="..."> aqui desde já, ver
seção 4):
  primary/info azul    bg-blue-100 text-blue-800     dark: bg-blue-900 text-blue-300
  secondary/cinza      bg-gray-100 text-gray-800     dark: bg-gray-700 text-gray-300
  success              bg-green-100 text-green-800   dark: bg-green-900 text-green-300
  danger               bg-red-100 text-red-800       dark: bg-red-900 text-red-300
  warning              bg-yellow-100 text-yellow-800 dark: bg-yellow-900 text-yellow-300
  info (ciano)         bg-cyan-100 text-cyan-800     dark: bg-cyan-900 text-cyan-300

Alertas / mensagens flash (.alert-*, com borda, p-3 my-3 text-sm
rounded-lg border):
  primary   text-blue-800 bg-blue-100 border-blue-200
  info      text-cyan-800 bg-cyan-100 border-cyan-200
  success   text-green-800 bg-green-100 border-green-200
  warning   text-yellow-800 bg-yellow-100 border-yellow-200
  danger    text-red-800 bg-red-100 border-red-200

Essas combinações já são seguras em termos de contraste (par -100/-800
no claro, -900/-300 no escuro) — diferente das cores hex puras (#22C55E
etc.) que reprovaram no teste de contraste feito antes.

painel logado), pode-se introduzir cor de destaque própria só ali, sem
tocar no painel administrativo/painel do lava-rápido.


3.1 ASSETS DE MARCA (FAVICON E LOGO, JÁ COPIADOS NA TASK-1)
------------------------------------------------------------------
A task-1 (Passo 5) já copia dois arquivos que ficavam soltos junto das
tasks (saas-lavagem-automotiva/favicon.ico e
logo-define-500x500_v3.png) pra dentro de public/ do projeto:

  public/favicon.ico          — usar via <link rel="icon"
                                href="{{ asset('favicon.ico') }}"> no
                                <head> de TODOS os layouts (admin,
                                painel do lava-rápido, público — task-14
                                e task-12).
  public/images/logo.png      — a logo em si (PNG 500x500,
                                transparente). Usar via
                                {{ asset('images/logo.png') }} no
                                cabeçalho/menu de cada layout (task-12,
                                seção 4; task-14, seções 2-3).

VERIFICAR antes de usar em cada lugar se a logo precisa ser
redimensionada: é um arquivo quadrado grande (500x500), então um
cabeçalho normal (logo pequena ao lado do nome do site/painel) precisa
de width/height explícito no HTML (ex: w-10 h-10 no Tailwind) — nunca
deixar o navegador exibir o arquivo original em tamanho pequeno sem
essas classes, senão carrega os 500x500 à toa. Em lugares que pedem uma
versão maior (ex: seção de rodapé/sobre da home, task-12), o arquivo
original já serve sem precisar redimensionar de verdade.
